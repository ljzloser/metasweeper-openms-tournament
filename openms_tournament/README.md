# OpenMS 比赛

浏览 OpenMS 进行中和待开始的比赛，检查本人是否打卡和剩余时间，登录后可开始打卡，
并读取本人的比赛标识。

1. 填写 OpenMS 用户 ID（个人主页对应的数字 ID），点击「保存并刷新」。0 表示未配置。
2. 列表的「比赛标识」列显示每场个人标识，双击标识可复制；选中进行中的比赛查看个人参赛时间。
3. 「我已打卡」和「打卡倒计时」列会显示个人参赛窗口。登录后可点击「一键打卡」；
   确认后逐场提交并显示结果，因为打卡会立即开始计时且不能撤回。也可单场打卡。
4. 选择一场当前有效参赛的比赛后，点击「设置到元扫雷」会重新检查所有当前有效比赛，
   并将每场比赛标识用英文半角逗号连接（不加空格），以支持同时参加多个比赛；规则见
   [OpenMS 比赛标识说明](https://openms.top/docs/zh/guide/identifier#tournament-token)。
5. 双击「比赛标识」列可复制单场标识。下方「当前总比赛标识」显示主程序当前实际设置的完整字符串，其旁边的「复制」按钮复制该值。
   如要应用到元扫雷，请先在插件管理器中授权「设置比赛标识」。
6. 自动维护比赛标识默认开启，OpenMS 每 5 分钟检查一次；
   标识不一致时，在主程序待开局（ready）状态自动应用。自动维护不会替用户打卡。
   关闭自动维护后，后台不再自动设置标识。插件始终按 OpenMS 规则合并所有有效的比赛标识。
7. 页面顶部仅在未授权时显示授权提示；当前对局出现不公平、非标准模式、预设局面约束或作弊控制时，
   在同一区域显示简短警示按钮，点击查看原因和处理方案。两项正常时整行隐藏，不占用空间。
   待开局状态不把主进程的 `is_fair=False` 当作不公平；插件不会自动修改设置。

浏览比赛和标识无需登录；打卡要求登录，并且账号需要满足 OpenMS 的实名或玩家认证条件。
自动上传比赛录像默认关闭。登录后勾选「自动上传录像」，插件会将之后完成的公平正式标准模式比赛胜局
加入持久化上传队列，并复用当前登录会话提交 EVF；不依赖主程序是否保存了本地录像。
有可上传的本地比赛录像时，工具栏会显示「手动上传」。关闭自动上传后仍可选一局手动提交。
重复录像收到网站的 `file / collision` 响应后，会显示「网站已存在」、丢弃队列副本并停止重试，不删除主程序录像。
上传成功后，插件页面最上方会单行显示录像编号、对局结果、难度、用时、3BV 和网站状态，页面可见时开始计时，5 秒后自动隐藏。
网络失败最多自动尝试三次。「上传记录」可查看结果和重试当前账号的失败项。
所有请求在后台串行并至少间隔一秒；上传接口每次只支持一份录像。收到 429 时整个会话按 `Retry-After` 冷却，
未提供等待时间则从 30 秒起逐步退避；不消耗普通上传失败重试次数，不会立即改传下一份录像。
比赛列表一次批量获取，个人成绩一次读取全部比赛录像。短时间重复查询复用缓存，写操作后立即失效。
一键打卡遇到限流会停止剩余提交，等待冷却后重新操作；已成功的打卡不会重复提交。
登录失效时暂停，重新登录原账号后恢复；队列不会跨账号上传。
超出当前比赛范围或所有匹配比赛的参赛上传窗口后，直接删除录像副本和整条上传记录，成功、重复、失败项同样清理。
多场比赛共用的录像保留到最后一场退出范围；没有当前比赛时清空上传记录。不保留历史，数据库自动回收空间。
截止时间清理不依赖登录或自动上传开关；比赛范围每五分钟刷新，查询失败时不据此清空数据。
录像包含多个比赛标识时只上传一次。上传成功不等于计入比赛，审核和成绩以网站结果为准。

登录后点击比赛所在行的「我的成绩」，或双击该行，查看当前账号的计分明细与已提交录像。双击已公开的标识仍可复制。
竞速周赛取最快 5 中 + 2 高；效率周赛按「用时 / IOE²」取最低 5 中 + 2 高；金羊杯取最快 20 初 + 12 中 + 5 高。
不足局数按比赛规定的上限补位；只计入网站审核通过的标准模式录像，金羊杯还按规则检查 3BV 下限。
窗口显示总成绩、各难度小计、计分录像、补位项，并逐条解释未计入原因。金羊杯的 3BV/s、STNB 独立统计，仅供参考。
计分明细右侧只用本插件数据库中匹配个人比赛标识的本地胜局计算预计成绩，关闭自动上传依然记录。
计算使用赛制的难度、取用局数、公式和补位规则，忽略模式、公平状态、资格门槛、上传和审核状态。
已打卡的进行中比赛会在列表显示两种成绩。双击计分项或录像行可在元扫雷中播放。
本地录像未保存或已清理时，仍可使用本地对局数据计算预计成绩。比赛结束后清理对应本地记录。
旧版本只保存了上传编号的录像，会在刷新成绩时按本地编号补齐计分数据。
退出登录、切换账号或比赛退出当前列表时，窗口内容清空。
时间均为北京时间（UTC+8）。设置中的「请求超时」默认为 8 秒。

也支持用户名密码登录：点击主界面的「登录 OpenMS」，在对话框里填写账号密码，刷新并手动输入图片验证码后登录。
登录后自动填入并锁定当前用户 ID。「检查登录状态」用于检测过期，「退出登录」清除会话。
插件设置中的「保持登录天数」是整数输入，范围 7–90，默认 30 天。也可在那里
配置默认用户名。设置为正数时会将 Cookie 保存到当前系统的安全凭据库（Windows Credential Manager、
macOS Keychain 或 Linux Secret Service），并在下次启动时验证。退出登录会
删除已保存 Cookie。修改有效天数后需重新登录才能更新服务器会话期限。密码不会保存，提交后立即清空输入框。插件依赖管理器需要安装随包提供的
`keyring` 依赖；如果系统没有可用的凭据库，插件会提示无法保持登录。
验证码或密码错误后，请重新刷新图片再试。

主程序状态通过本地只读查询每 3 秒更新，OpenMS 网络轮询为每 5 分钟一次。自动维护只在有
有效参赛标识时设置，不会清除没有比赛时的现有标识。OpenMS 请求直接使用插件管理器内置的 `requests`，不使用 OpenAPI SDK。插件使用系统凭据库
保存可选的持久会话，并需要通过插件管理器安装随包提供的 `keyring` 依赖。
插件需要宿主提供 `SetRaceIdentifierCommand`。
